# Exa Websets, Monitors, hosted MCP server, and wiring Exa into a Claude agent (state as of 13 Nov 2026)

Method: every fact below comes from Exa's live docs pulled as markdown on 13 Nov 2026 (`https://exa.ai/docs/<page>.md`, indexed at `https://exa.ai/docs/llms.txt`; `docs.exa.ai` now redirects there), from a shallow clone of `exa-labs/exa-mcp-server` (package v3.4.3, last commit 3 Nov 2026), from the `exa-labs/websets-mcp-server` README, and from current Anthropic and OpenAI docs. "Documented" means a URL is cited. "Inferred" means my own reading, flagged as such.

**The big news for the team:** in 2026 Exa moved its centre of gravity. **Exa Agent** (Jun 2026) is now the recommended product for list-building and enrichment. The docs tell new users to use Exa Agent rather than Websets. The standalone **Monitors API** (Mar 2026) is the "recurring searches" product. The hosted MCP server has been cut down to 4 tools: `web_search_exa`, `web_fetch_exa`, `web_search_advanced_exa` and `agent_run`. The older company, people, LinkedIn, deep-research and code tools are deprecated.

## 1. Websets: what it is, API, timing, verification evidence, limits, demo-fitness, MCP

### Takeaway
Websets is an async list-building API. You give it a query, a target count, up to 5 criteria and some enrichments. Each item it returns carries per-criterion `reasoning`, a `satisfied` value (yes/no/unclear) and `references` (url, title, snippet). It is now positioned as a legacy or maintenance product: Exa says to start new list-building with Exa Agent. The Websets API also needs a **paid Websets plan** (Websets credits are separate from API credits), and small websets take "minutes". That makes it a background job, not something for a live 60-second demo. Exa Agent (`agent_run`, or `POST /agent/runs`) is the better way to show "verified lists of people, companies and opportunities".

### Cited Findings
- Definition: "Websets is a list-building and data enrichment API for companies, people, and other entities on the web. A Webset starts with a natural-language query and a target item count. Add criteria that every result must satisfy and enrichment fields… Results arrive asynchronously through the dashboard, API, or webhooks." — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- **Positioning in 2026:** "Starting a new list-building or enrichment workflow? Use Exa Agent. Use this guide to maintain or extend an existing Websets integration. The Websets API requires a paid Websets plan; Search API credits and Websets credits are separate." — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- **Timing:** "`count` is a target, not a guarantee… Small websets finish in minutes; requests for 1,000+ items scan a much larger candidate pool and take significantly longer. The Free plan caps a webset at 25 verified results." — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- Pipeline: (1) define the search; (2) "Websets finds candidates and checks each one against your criteria. Only matching results become items"; (3) enrichments run per verified item (for example CEO name, funding, contact info); (4) poll, use webhooks, or watch the dashboard. — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- Billing: verified results, enrichments, contact data, imports and API previews all consume Websets credits. Rates are on `https://websets.exa.ai/billing`. — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- **Base URL:** `POST https://api.exa.ai/websets/v0/websets/` with `Authorization: Bearer $EXA_API_KEY` (or `x-api-key`). — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md), [llms.txt](https://exa.ai/docs/llms.txt)
- **Create-webset `search` params:** `query` (1–5000 chars; "Any URLs provided will be crawled and used as additional context"); `count` (default 10, min 1); `entity` (detected from the query if omitted; entity types are `company`, `person`, `article`, `research_paper`, `custom`); `criteria` (1–5 items, generated from the query if omitted); `maxPeoplePerCompany`; `recall` (boolean, returns an estimate of how many relevant results exist); `exclude` (`[{source: "import"|"webset", id}]`); `scope` (search within imports or websets, with optional `relationship: {definition, limit 1–10}` for "find the X related to these entities"). Top-level fields: `import`, `enrichments`, `exclude`, `externalId`, `metadata`. — [Create a webset](https://exa.ai/docs/websets/api/websets/create-a-webset.md)
- Enrichments: `description`, `format` (auto-selected when omitted; options include text, date, number, options, email, phone, url), and `options` (up to 150) for multiple choice. — [Create a webset](https://exa.ai/docs/websets/api/websets/create-a-webset.md), [Create an enrichment](https://exa.ai/docs/websets/api/websets/enrichments/create-an-enrichment.md)
- **Evidence on each item:** a Webset Item has `id`, `source`, `sourceId`, `websetId`, `properties` (entity-specific; for a person: url, description of relevance, name, location, position, company, image, work history, education), `evaluations[]`, `enrichments[]`, `createdAt` and `updatedAt`. Each `WebsetItemEvaluation` holds `criterion`, `reasoning`, `satisfied` (`yes`/`no`/`unclear`) and `references[]` of `{title, snippet, url}`. Each enrichment result holds `status` (pending/completed/canceled), `format`, `result`, `reasoning` ("when an Agent is used") and `references[]` of `{title, snippet, url}`. — [Get an item](https://exa.ai/docs/websets/api/websets/items/get-an-item.md)
- **Preview endpoint:** "Returns how a search query will be interpreted before you create a Webset, including the detected entity, generated criteria, and suggested enrichments." (Previews cost credits.) — [Preview a webset](https://exa.ai/docs/websets/api/websets/preview-a-webset.md), [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- Other endpoints: get, update, delete, list, cancel; items list/get/delete; searches create/get/cancel; enrichments create/get/update/delete/cancel; imports (CSV upload to `uploadUrl` within 1 hour; usable to enrich, `scope` or `exclude`); webhooks (create/get/update/delete/list/attempts, with signature verification); events list/get; teams (concurrency usage and limits). — [llms.txt](https://exa.ai/docs/llms.txt)
- **Event types** (retained 60 days): `webset.created|deleted|paused|idle`, `webset.search.created|updated|completed|canceled`, `webset.item.created`, `webset.item.enriched`, `import.created|completed`, `webset.export.created|completed`, `monitor.created|updated|deleted`, `monitor.run.created|completed`. — [Event types](https://exa.ai/docs/websets/api/events/types.md)
- **SDK:** Python `exa.websets.create(params=CreateWebsetParameters(search={...}, enrichments=[CreateEnrichmentParameters(description=..., format="text")]))`, `exa.websets.wait_until_idle(id)`, `exa.websets.items.list(webset_id=...)`. JS: `exa.websets.create({...})`, `exa.websets.waitUntilIdle(id, {timeout: 60000, pollInterval: 2000, onPoll})`, `exa.websets.items.list(id, {limit})`. Each webset has a `dashboardUrl`. — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- Troubleshooting guidance: over-constrained criteria cause short lists. Make the rarest attribute an enrichment, not a criterion. "Open-ended questions… and single-fact lookups belong in Search." — [Websets quickstart](https://exa.ai/docs/websets/quickstart.md)
- **Websets MCP server exists:** repo `exa-labs/websets-mcp-server` (default branch `master`). It has a hosted HTTP endpoint at `https://websetsmcp.exa.ai/mcp`, authenticated with `Authorization: Bearer <EXA_API_KEY>` (or `?exaApiKey=` as a fallback). Claude Code: `claude mcp add --transport http websets https://websetsmcp.exa.ai/mcp --header "Authorization: Bearer YOUR_API_KEY"`. Tools: `create_webset`, `list_websets`, `get_webset`, `update_webset`, `delete_webset`, `preview_webset`, `list_webset_items`, `get_item`, `create_search`, `get_search`, `cancel_search`, `create_enrichment`, `get_enrichment`, `cancel_enrichment`, `create_webhook`, `get_webhook`, `update_webhook`, `delete_webhook`, `list_webhooks`, `create_import`, `get_import`, `list_imports`, `list_events`. The README warns: "Do not install or run `websets-mcp-server` via npm/npx. That unscoped npm package name is not owned by Exa." — [websets-mcp-server README](https://github.com/exa-labs/websets-mcp-server)
- **The successor, Exa Agent:** an "async, usage-based web research agent API for… list building, enrichment, and deep research". Returns `output.text`, `output.structured` (validated against your `outputSchema`), `output.grounding` (citations per field) and `costDollars`. Endpoint `POST https://api.exa.ai/agent/runs`. Supports SSE streaming (`Accept: text/event-stream`, events `agent_run.created|started|completed|failed|cancelled`, plus `agent_run.source.added` live previews). SDK: `exa.agent.runs.create(...)` and `exa.agent.runs.poll_until_finished(id)`. "Exa Agent is higher-latency and async by design." Run data is retrievable only "for up to 10 minutes after it reaches a terminal state". — [Exa Agent quickstart](https://exa.ai/docs/agent/quickstart.md)
- Agent effort levels and fixed prices: `minimal` $0.012, `low` $0.025, `medium` $0.10, `high` $0.50, `xhigh` $1.00 per request; `auto` is metered (default cap $5); `ultra` is metered (default cap $20); `budget.maxCostDollars` ranges $1–$100. Guidance: "Start with `medium` for standard single-entity research. Drop to `low` or `minimal` when cost and latency matter." The docs give no latency guarantees: "Treat effort modes as quality/cost/runtime tradeoffs rather than strict latency guarantees." — [Exa Agent quickstart](https://exa.ai/docs/agent/quickstart.md)
- Schema advice for verification: make fields that may not be verifiable nullable and leave them out of `required`, and use a `verdict` enum that separates `cannot_verify` from `absent`. — [Exa Agent quickstart](https://exa.ai/docs/agent/quickstart.md)

### Inferences
- Inferred: Websets is not usable in a live 60-second judge demo. It needs a paid Websets plan (the hackathon may or may not supply one), and "small websets finish in minutes". Use it only as a pre-built background list, if at all.
- Inferred: for the "verified list" moment on stage, use Exa Agent with `effort: "low"` or `"medium"`, a small bounded `outputSchema` (for example 5 items with `source_url` and `evidence` fields), and SSE streaming. That shows sources arriving live (`agent_run.source.added`) and then a grounded table. Pair it with fast `/search` calls (`auto` ~1 s) so the UI never sits idle.
- Inferred: the Websets `evaluations[].reasoning` plus `references[].snippet` shape is the best existing model for a "why we trust this row" UI. Mirroring it with Exa Agent `output.grounding` is a strong way to score on "how clearly sources are shown".

### Gaps
- No documented per-item or per-webset latency in seconds, only "minutes". The real time to the first `webset.item.created` event is undocumented.
- Exact Websets plan prices and whether the free API credits cover any Websets API usage. The page points to `websets.exa.ai/billing`, which needs login. (The pricing researcher covers this.)
- Whether the hosted Websets MCP endpoint is still maintained, given that Websets is now "maintenance". No deprecation notice was found, but no 2026 changelog entry mentions it either.

## 2. Monitors: Websets monitor vs Search Monitors, API, schedule, delivery, limits

### Takeaway
There are two products. (a) The **Monitors API** (launched 30 Mar 2026) at `POST https://api.exa.ai/monitors`: a scheduled Exa search with `trigger: {type: "interval", period: "1h"|"6h"|"1d"|"7d"}` (minimum 1 hour) that dedupes against previous runs. It delivers by webhook, which must be HTTPS and public, and runs can also be polled. Each run returns `output.results`, `output.content` (a summary, or JSON if you pass `outputSchema`) and `output.grounding`. It costs $2 per 1k requests. (b) The older **Websets monitors** at `POST https://api.exa.ai/websets/v0/monitors`: a 5-field cron (at most once a day) plus a timezone, with `behavior.type: "search"`; run types are `search` or `refresh`. Exa's brief phrase "Monitors for recurring searches" matches (a). For a demo, use `POST /monitors/{id}/trigger` to fire a run on demand.

### Cited Findings
- "Monitors is Exa's web monitoring API. Each monitor runs Exa searches on a recurring schedule and delivers results to a webhook endpoint." On each run Exa "executes the configured search, filters by time, removes results or findings the monitor has already returned, and sends the new output to your webhook." "Write the query around the ongoing signal you want to track rather than adding a moving date range yourself." — [Monitors quickstart](https://exa.ai/docs/monitors/quickstart.md)
- Launched: "March 30, 2026 — Introducing Exa Monitors… deduplicated against previous runs so you only get new content." — [Changelog](https://exa.ai/docs/changelog.md)
- **Create request:**
  ```json
  POST https://api.exa.ai/monitors
  {"name": "...", "search": {"query": "...", "numResults": 10, "contents": {"highlights": true}},
   "trigger": {"type": "interval", "period": "1d"},
   "outputSchema": {...optional...}, "metadata": {...optional...},
   "webhook": {"url": "https://example.com/webhooks/exa", "events": ["monitor.run.completed"]}}
  ```
  The response includes `id`, `status`, `nextRunAt` and a one-time `webhookSecret`. SDK: `exa.monitors.create({...})`, `exa.monitors.trigger(id)`, `exa.monitors.runs.list(id, limit=1)`. — [Monitors quickstart](https://exa.ai/docs/monitors/quickstart.md)
- `search` accepts only `query`, `numResults` (1–100), `includeDomains`/`excludeDomains` and `contents` (highlights, text, summaries). "No other Search options are accepted." — [Monitors quickstart](https://exa.ai/docs/monitors/quickstart.md), [Create a monitor](https://exa.ai/docs/reference/monitors/create-a-monitor.md)
- **Schedule:** "The minimum interval is one hour. Use a single duration such as `1h`, `6h`, `1d`, or `7d`." The schedule is anchored to the creation time, "but each run may be delayed by up to 30 minutes". `trigger.type` "Currently only `interval` is supported." If you omit `trigger`, the monitor is manual-only. Runs do not overlap: a new scheduled run cancels a still-running previous one. — [Monitors quickstart](https://exa.ai/docs/monitors/quickstart.md), [Create a monitor](https://exa.ai/docs/reference/monitors/create-a-monitor.md)
- Status values: `active`, `paused` (manual trigger only) and `disabled` ("auto-disabled after 10 consecutive" failures; the text is truncated in the spec). Run statuses: `pending`, `running`, `completed`, `failed` (with `failReason`), `cancelled`. `output` is null until the run completes. — [Create a monitor](https://exa.ai/docs/reference/monitors/create-a-monitor.md), [Monitors quickstart](https://exa.ai/docs/monitors/quickstart.md)
- **Output:** `output.results` (new pages) and `output.content` (a text summary by default, or JSON matching `outputSchema`). "Sources for synthesized fields are returned automatically in `output.grounding`" as `[{field, citations:[{title,url}], confidence}]`. `outputSchema` is limited to 10 properties in total and 2 levels of nesting, and it "adds about 2 seconds of synthesis latency". It is not available with the `lite` search type. — [Monitors quickstart](https://exa.ai/docs/monitors/quickstart.md), [Create a monitor](https://exa.ai/docs/reference/monitors/create-a-monitor.md)
- **Delivery:** webhook events are `monitor.created`, `monitor.updated`, `monitor.deleted`, `monitor.run.created` and `monitor.run.completed` (all are sent if `events` is omitted). The webhook URL "must not point to localhost or private IP ranges", must be HTTPS, and redirects are not followed. Signature header: `Exa-Signature: t=<ts>,v1=<hmac-sha256 of "<ts>.<raw body>">`, keyed with `webhookSecret`. `metadata` is echoed in deliveries, which lets you route a result to the right user. You can also poll with `GET /monitors/{id}/runs` and `GET /monitors/{id}/runs/{runId}`. No email delivery is documented. — [Monitors quickstart](https://exa.ai/docs/monitors/quickstart.md), [Create a monitor](https://exa.ai/docs/reference/monitors/create-a-monitor.md), [llms.txt](https://exa.ai/docs/llms.txt)
- Other endpoints: list (filter by status, with a cursor), get, update (partial `search`; `trigger: null` removes the schedule), delete, trigger ("Works for monitors with status active or paused"), and a batch delete/pause/unpause with `dry_run` defaulting to true. — [llms.txt](https://exa.ai/docs/llms.txt)
- Price: Monitors cost "$2 / 1k requests". — [Pricing](https://exa.ai/docs/admin/pricing.md)
- **Websets monitors (the legacy variant):** `POST https://api.exa.ai/websets/v0/monitors` with `{websetId, cadence: {cron, timezone (default Etc/UTC)}, behavior: {type: "search", config: {query?, criteria? (≤5), entity?, count, behavior: "append" default}}, metadata}`. The cron "must be a valid Unix cron with 5 fields. The schedule must trigger at most once per day." `MonitorRun.type` is `search` or `refresh`. The docs now redirect readers: "To run a recurring Exa search and send new results to your webhook, use the Monitors API." — [Create a Websets monitor](https://exa.ai/docs/websets/api/monitors/create-a-monitor.md)

### Inferences
- Inferred "keep watching" pattern for a personal butler: when the user approves a task such as "tell me when a 2-bed flat under €1,200 in Otaniemi appears" or "watch for this visa rule changing", the agent creates a monitor with `metadata: {user_id, task_id}`, a precise `query`, `includeDomains` (official sources), a small `outputSchema` and `period: "1d"`. A webhook receiver on a public HTTPS host (for example a Vercel function or a tunnel) verifies `Exa-Signature`, then wakes Claude to judge whether the new results matter and drafts a notification for the user to approve. Inside the demo, press "check now", which calls `POST /monitors/{id}/trigger`, then poll `runs` and show the new grounded results. This avoids waiting for an hourly schedule.
- Inferred: localhost cannot receive monitor webhooks (private addresses are refused). For the demo either deploy the receiver or skip webhooks and poll runs.

### Gaps
- No documented cap on monitors per team, and no documented typical run duration. The full "disabled after 10 consecutive …" sentence is truncated in the spec text I read.
- Whether "$2 / 1k requests" counts runs or underlying searches, and whether `outputSchema` adds cost. (Pricing researcher.)

## 3. Hosted Exa MCP server: URL, auth, tools, restriction, rate limits, repo

### Takeaway
The URL is `https://mcp.exa.ai/mcp` (Streamable HTTP). There are three auth modes. Keyless gives search and fetch only, at a free per-IP limit. OAuth uses `?login`. An API key can go in the `x-api-key` header, in `Authorization: Bearer`, or in `?exaApiKey=`. Current tools are `web_search_exa` and `web_fetch_exa` (on by default), `web_search_advanced_exa` (opt-in), and `agent_run` (on by default once authenticated). Choose tools with `?tools=a,b,c`; this replaces the defaults. Nine legacy tools (`company_research_exa`, `people_search_exa`, `linkedin_search_exa`, `deep_researcher_start/check`, `deep_search_exa`, `crawling_exa`, `get_code_context_exa`) still exist in code but are marked deprecated and off by default.

### Cited Findings
- URL and keyless trial: "`https://mcp.exa.ai/mcp`. No API key is needed to try search and fetch, at a free rate limit. Sign in or add an API key to use Exa Agent." The server is open source on GitHub (`exa-labs/exa-mcp-server`) and npm (`exa-mcp-server`). — [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- **Auth modes table:** Keyless means connecting to `https://mcp.exa.ai/mcp`, and "`agent_run` is unavailable". OAuth means `https://mcp.exa.ai/mcp?login`, described as for "Interactive clients, marketplace installs, production usage". API key means `x-api-key` header, for "Clients without MCP OAuth". — [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- Source code confirms more options: "Supports API key via header (recommended) or URL query parameter: `x-api-key: YOUR_KEY`, `Authorization: Bearer YOUR_KEY`, `?exaApiKey=YOUR_KEY` (backwards compatible)… Priority: x-api-key header > Authorization header > URL query parameter > environment variable." Other URL params: `?tools=`, `?debug=true`, `?agentCallWindowMs=45000`. The README also gives `https://mcp.exa.ai/mcp/oauth` as an alternative OAuth URL. — [exa-mcp-server api/mcp.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/api/mcp.ts), [README](https://github.com/exa-labs/exa-mcp-server)
- **Tool list (docs):** `web_search_exa` ("Enabled by default"), `web_fetch_exa` ("Enabled by default"), `web_search_advanced_exa` ("Available when opted in"), `agent_run` ("Enabled by default with OAuth or API key"). To enable all four: `https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa,web_search_advanced_exa,agent_run`. "An explicit `tools` list replaces the defaults." — [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- Conflict: the GitHub README lists `agent_run` under "Optional Tools (enable via the `tools` parameter)", but the docs and `src/toolRegistry.ts` (`agent_run: enabled: true, requiresUserProvidedApiKey: true`) say it is on by default once authenticated. Listing it explicitly in `?tools=` is safe either way. — [README](https://github.com/exa-labs/exa-mcp-server); [toolRegistry.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/toolRegistry.ts)
- **`web_search_exa`** — params: `query` (string; "describe the ideal page, not keywords"; an inline `category:people` or `category:company` focuses on LinkedIn-style profiles or companies), `numResults` (default 10). It wraps `POST /search` with `type: "auto"` (configurable server default) and `contents: {highlights: true}` (or `{dynamic: true}` when `?dynamicHighlights=true`). Timeout 60 s. Annotations: readOnly, openWorld, idempotent. — [webSearch.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/webSearch.ts), [config.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/config.ts)
- **`web_fetch_exa`** — params: `urls` (string[], batch several), `maxCharacters` (default 3000 per page). It wraps the Contents endpoint (`/contents`). Timeout 60 s. — [webFetch.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/webFetch.ts), [config.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/config.ts)
- **`web_search_advanced_exa`** — params: `query`, `numResults` (1–100), `type` (`auto` recommended; `lite` is low-cost and cached; `instant`/`fast` are legacy), `category` (`company`, `publication`, `news`, `pdf`, `github`, `personal site`, `people`, `financial report`), `includeDomains`, `excludeDomains`, `startPublishedDate`, `endPublishedDate`, `startCrawlDate`, `endCrawlDate`, `includeText`, `excludeText`, `userLocation` (ISO country), `moderation`, `additionalQueries`, `textMaxCharacters`, `contextMaxCharacters`, `enableSummary`, `summaryQuery`, `enableHighlights`, `highlightsMaxCharacters`, `highlightsQuery`, `maxAgeHours` (0 means always live-crawl), `livecrawlTimeout`, `subpages` (1–10), `subpageTarget`. It wraps `/search`. Timeout 300 s. Advanced search "does not require authentication". — [webSearchAdvanced.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/webSearchAdvanced.ts), [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- **`agent_run`** — params: `query` or `runId` (not both), `systemPrompt`, `outputSchema` (JSON Schema; "Prefer a top-level object with bounded arrays and source/evidence fields"), `input.data[]`, `input.exclusion[]`, `dataSources[]` (up to 5 Exa Connect providers: `fiber`, `financial_datasets`, `similarweb`, `baselayer`, `affiliate`, `particle`, `jinko`, `polymarket`, `macrobond`), `previousRunId`, `effort` (`minimal|low|medium|high|xhigh|ultra|auto`; the tool says "Defaults to low"), `budget.{maxCostDollars, maxDurationSeconds}`. Output: `{id, status: completed|running|failed|cancelled, outputReady, output.{text, structured, grounding, files}, usage, costDollars, error, message}`. It wraps the Agent API. If the run outlasts the MCP call window (default 45 s), it returns `status: "running"` with an `id`, and you call again with `runId`. It streams progress notifications. Legacy names (`agent_create_run`, `agent_run_stream`, `agent_wait_for_run`, …) forward to `agent_run`. — [agentRun.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/agentRun.ts), [toolRegistry.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/toolRegistry.ts), [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- Note on defaults: the Agent API docs say the default effort is `auto` (metered, $5 cap), while the MCP tool description says "Defaults to low". Pass `effort` explicitly. — [Exa Agent quickstart](https://exa.ai/docs/agent/quickstart.md); [agentRun.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/agentRun.ts)
- **Deprecated tools** (still registered, off by default): `get_code_context_exa` ("Use web_search_exa instead"), `company_research_exa`, `people_search_exa` and `linkedin_search_exa` ("Use web_search_advanced_exa instead"), `deep_search_exa`, `deep_researcher_start`, `deep_researcher_check`, `crawling_exa` ("Use web_fetch_exa instead"). — [toolRegistry.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/toolRegistry.ts)
- **Dynamic Highlights (beta):** `https://mcp.exa.ai/mcp?dynamicHighlights=true` chooses highlights "across all results under one shared budget", so less text reaches the agent's context. — [README](https://github.com/exa-labs/exa-mcp-server)
- **Rate limits:** free use is limited per IP and applies only to `tools/call`, not to list or initialize. In code, the defaults are `RATE_LIMIT_QPS` "default: 2" and `RATE_LIMIT_DAILY` "default: 50". An API key bypasses this limit. The 429 message tells users to create a key. — [api/mcp.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/api/mcp.ts). "Keyless access requires an IPv4 connection made directly to `https://mcp.exa.ai/mcp`. From IPv6 or a proxied network path, sign in with OAuth or add an API key" (otherwise a 403). — [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- Free credits: "The Free Tier gives you $10 in credits (up to 2,500 Lite searches) the day you sign up, and your free balance resets to $10 on the first of every month. No payment method required." — [Pricing](https://exa.ai/docs/admin/pricing.md)

### Inferences
- Inferred: 2 QPS and 50 calls/day per IP are only code defaults. The production values may differ, and the server hides them ("limit set to 0"). Never rely on keyless mode for judges' live queries: a hackathon venue NAT shares one IP across hundreds of teams and may be IPv6. Get a key.
- Inferred: the Anthropic MCP connector (from Anthropic's servers) counts as a "proxied network path" with a shared IP. Always send a key there.

### Gaps
- The production keyless rate limit is undisclosed.
- No documented per-tool cost when called through MCP. It presumably matches the underlying endpoint pricing, but this is not stated.

## 4. Using Exa MCP from Claude Code, the Anthropic Messages API connector, the Claude Agent SDK, and the OpenAI Responses API

### Takeaway
All four take the URL `https://mcp.exa.ai/mcp`. Claude Code and the Agent SDK accept arbitrary headers, so use `x-api-key`. The Anthropic Messages API MCP connector accepts only `authorization_token`, which it sends as a Bearer token. Exa's server accepts `Authorization: Bearer <EXA_API_KEY>`, so pass the Exa key there (inferred from source), or put `?exaApiKey=` in the URL. The OpenAI Responses API uses `{type: "mcp", server_url, authorization, allowed_tools, require_approval}`.

### Cited Findings
- **Claude Code (plugin):** `claude plugin install exa@claude-plugins-official` (or `/plugin`, search Exa). It bundles the MCP server plus the `search` and `exa-agent` skills. — [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md), [README](https://github.com/exa-labs/exa-mcp-server)
- **Claude Code (manual):** `claude mcp add --transport http <name> <url>` with `--header "X-API-Key: your-key-here"` or `--header "Authorization: Bearer your-token"`. `--scope project` writes to a committed `.mcp.json`. In JSON, `type` accepts `streamable-http` as an alias for `http`. — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp.md). Example (applied to Exa):
  ```bash
  claude mcp add --transport http exa "https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa,web_search_advanced_exa,agent_run" --header "x-api-key: $EXA_API_KEY"
  ```
- **Anthropic Messages API MCP connector** (beta): header `anthropic-beta: mcp-client-2025-11-20`, or the newer `mcp-client-2026-09-15`, which "includes everything `mcp-client-2025-11-20` does" plus tool-list pinning (`mcp_tool_listing` blocks and `tools` on the toolset). Request shape: `mcp_servers: [{type: "url", url: "https://…", name, authorization_token?}]` plus `tools: [{type: "mcp_toolset", mcp_server_name, default_config: {enabled, defer_loading}, configs: {tool_name: {...}}, cache_control?}]`. Every server must be referenced by exactly one toolset. Allowlist: `default_config.enabled: false` plus `configs.<tool>.enabled: true`. Responses contain `mcp_tool_use` blocks (`id`, `name`, `server_name`, `input`) and `mcp_tool_result` blocks (`tool_use_id`, `is_error`, `content`). Limitations: "only tool calls are currently supported", the URL must be public HTTPS (Streamable HTTP or SSE), and the feature is not ZDR-eligible. Python uses `client.beta.messages.create(..., mcp_servers=[...], tools=[{"type":"mcp_toolset",...}], betas=["mcp-client-2025-11-20"])`. The connector supports claude-opus-5-5, claude-fable-5-2 and the other current models. — [Anthropic MCP connector](https://platform.claude.com/docs/en/agents-and-tools/mcp-connector)
  ```python
  # Inferred application to Exa (auth via Bearer, which Exa's server accepts per api/mcp.ts)
  resp = client.beta.messages.create(
      model="claude-opus-5-5", max_tokens=4000, betas=["mcp-client-2026-09-15"],
      messages=[{"role": "user", "content": user_task}],
      mcp_servers=[{"type": "url", "name": "exa",
                    "url": "https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa,agent_run",
                    "authorization_token": os.environ["EXA_API_KEY"]}],
      tools=[{"type": "mcp_toolset", "mcp_server_name": "exa"}])
  ```
- Mid-conversation MCP servers: "With the `inline-tools-2026-09-15` beta header as well, you can add an MCP server partway through a conversation." — [Anthropic MCP connector](https://platform.claude.com/docs/en/agents-and-tools/mcp-connector)
- **Claude Agent SDK:** `options.mcpServers` (TS) or `mcp_servers` (Python) with `{type: "http" | "sse", url, headers: {...}}`. Tools are named `mcp__<server>__<tool>`. Use `allowedTools: ["mcp__exa__*"]` to auto-approve; the docs say "Prefer `allowedTools` over permission modes for MCP access." Tool search (deferral) is on by default; `alwaysLoad: true` exempts a server. — [Agent SDK MCP](https://code.claude.com/docs/en/agent-sdk/mcp.md). Applied to Exa:
  ```ts
  query({ prompt, options: {
    mcpServers: { exa: { type: "http", url: "https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa,agent_run",
                         headers: { "x-api-key": process.env.EXA_API_KEY! } } },
    allowedTools: ["mcp__exa__*"] } })
  ```
- **OpenAI Responses API:** a `tools` entry of `{"type": "mcp", "server_label": "...", "server_description": "...", "server_url": "https://...", "require_approval": "never", "allowed_tools": [...], "authorization": "<oauth access token>"}`. — [OpenAI MCP guide](https://developers.openai.com/api/docs/guides/tools-connectors-mcp). Exa's Codex snippet: `codex mcp add exa --url https://mcp.exa.ai/mcp`. — [README](https://github.com/exa-labs/exa-mcp-server). Exa Agent is also reachable through an OpenAI-compatible Responses API at `https://api.exa.ai` with `model: "exa-agent"`. — [Exa Agent quickstart](https://exa.ai/docs/agent/quickstart.md)
- Other clients: Cursor, VS Code (`.vscode/mcp.json` with `"type":"http"`), and `mcp-remote` for stdio-only clients. Local stdio: `npx -y exa-mcp-server` with `EXA_API_KEY`. — [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)

### Inferences
- Inferred: `authorization_token` = Exa API key should work, because Exa's handler reads `Authorization: Bearer YOUR_KEY` as an API key. Fallback: `?exaApiKey=` in the URL. That keeps the key in server-side code only and must never reach the browser.
- Inferred: with the Messages API connector, Anthropic's infrastructure runs the MCP call, so your app sees `mcp_tool_use` and `mcp_tool_result` blocks after the fact. You can still render sources from them, but you cannot change parameters, cache, or add retries.

### Gaps
- Whether the OpenAI `mcp` tool accepts arbitrary `headers` today. The current page shows only `authorization`.
- Not live-tested (no key); the Bearer-as-API-key path for the Anthropic connector is inferred from source.

## 5. MCP vs calling the Exa API directly as custom tools (and what Exa recommends)

### Takeaway
For a product demo, call the Exa SDK directly inside our own Claude tool loop. Exa's own "Anthropic Tool Calling" page tells application builders to do exactly that with `exa.anthropic.web_search()`, `get_contents()` and `handle_tool_use()`. Exa positions the hosted MCP server and the plugins for assistants and coding agents (Claude Code, Desktop, Cursor, ChatGPT). The direct route gives full control over `highlights`, `outputSchema`, `includeDomains`, `maxAgeHours`, `type: lite|auto|deep` and `objective`. It also exposes `costDollars`, `requestId`, `searchTime`, `warnings` and `notices` for display, and lets you stream exactly what the agent is reading to the UI.

### Cited Findings
- Exa for applications: "The Exa SDKs ship ready-made web search and page reading tools for Anthropic, so you don't have to hand-write the tool schema, parse `tool_use` blocks, or format Exa results yourself." — [Anthropic Tool Calling](https://exa.ai/docs/integrations/tool-calling/anthropic.md)
- Exa MCP's purpose: "Use Exa MCP to improve the built-in web search in ChatGPT, Claude, and MCP-compatible tools". The install tabs cover ChatGPT, Codex, Claude Code, Desktop, Cursor, VS Code and other assistant clients. OAuth is described as for "Interactive clients, marketplace installs, production usage". — [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- Docs header for agents: "Prefer the official SDKs, `exa-py`… and `exa-js`… Tool-using agents can call Exa without writing code through the hosted MCP server." — [llms.txt](https://exa.ai/docs/llms.txt)
- In the SDK helpers, "The model picks the search `query` and `objective` and the `urls` to read; everything else is fixed when you create the tool, so it can't change what gets crawled or extracted." — [Anthropic Tool Calling](https://exa.ai/docs/integrations/tool-calling/anthropic.md)
- The MCP `web_search_exa` exposes only `query` and `numResults` and hard-codes `type: auto` and highlights. Advanced controls need `web_search_advanced_exa`, where the model chooses the parameters. — [webSearch.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/webSearch.ts), [Exa MCP](https://exa.ai/docs/get-started/exa-mcp.md)
- Observability advice: "Record `requestId`, `searchTime`, and `costDollars` so regressions are reproducible." Search responses now include `warnings` (fields with no effect) and `notices` (how results were produced). — [Search best practices](https://exa.ai/docs/search/best-practices.md), [Changelog Oct 19 2026](https://exa.ai/docs/changelog.md)
- Latency: `auto` takes about 1 s, `lite` about 300 ms (cached content only), `deep-lite` about 4 s, `deep` 4–15 s, `deep-reasoning` 12–40 s (legacy). — [Search quickstart](https://exa.ai/docs/search/quickstart.md), [Pricing](https://exa.ai/docs/admin/pricing.md)

### Inferences
- Inferred trade-offs for our demo:
  - *Control:* the direct SDK lets us fix `includeDomains` for trusted sources, `maxAgeHours: 0` for live prices, `userLocation: "FI"`, a schema for `deep`, and so on. With MCP the model picks these, or cannot pick them at all.
  - *Cost visibility:* the direct API returns `costDollars` per call, which we can show in the UI ("this task cost €0.03 of web research"). MCP output is pre-formatted text.
  - *Latency:* the direct route skips one network hop (our server, then Exa) versus Anthropic, then MCP, then Exa. It can also run searches in parallel.
  - *Showing sources:* we own the raw JSON (url, title, publishedDate, highlights, favicon or image), so we can render a live "what the agent is reading" panel and citation chips.
  - *Reliability:* our own retries and timeouts, and no dependence on beta connector headers or MCP tool-list changes (the 2026 tool consolidation already broke old tool names).
- Inferred best hybrid: build the product on the direct SDK. Also mention, or show, the same agent working in Claude Code through the Exa plugin or MCP. Use Exa Agent through the API (`/agent/runs` with SSE) rather than through `agent_run` over MCP, so progress events can be streamed to the UI.

### Gaps
- Exa never states an explicit "use MCP for coding assistants, SDK for products" rule. The recommendation is inferred from how the pages are organised and worded.

## 6. Exa's own guidance for tool use with Claude and other frameworks

### Takeaway
Exa recommends two tools, `web_search` (`type: "auto"`, `num_results: 10`, `contents: {highlights: true}`) and `get_contents`. Add a required `objective` string to the search tool, using Exa's exact description text. Keep the loop going until no `tool_use` blocks remain. If you also use Anthropic's built-in `web_search_20250305`, rename Exa's tool. Write queries that describe the ideal page.

### Cited Findings
- Python: `tools=[exa.anthropic.web_search(), exa.anthropic.get_contents()]`, then `exa.anthropic.handle_tool_use(response)` returns the `tool_result` blocks. JS: `exa.anthropic.webSearch()`, `getContents()`, `await exa.anthropic.handleToolUse(response)`. Defaults: `web_search` runs `exa.search(query, type="auto", num_results=10, contents={"highlights": True})`; `get_contents` returns page text capped at 10,000 chars in Python. "We recommend the defaults." — [Anthropic Tool Calling](https://exa.ai/docs/integrations/tool-calling/anthropic.md)
- "A real agent keeps `tools` on every request and repeats the handler step until the model replies without `tool_use` blocks." — [Anthropic Tool Calling](https://exa.ai/docs/integrations/tool-calling/anthropic.md)
- Name clash: "Anthropic requires tool names to be unique, so a custom name lets the Exa tool run alongside Anthropic's built-in `web_search_20250305` server tool": `exa.anthropic.web_search(name="exa_web_search")`. Unknown tools come back as `Error: unknown tool "<name>"`, so replace those with your own tool results. Provider-neutral specs are `exa.tools.web_search()` and `exa.tools.get_contents()`, each with a `.run`. — [Anthropic Tool Calling](https://exa.ai/docs/integrations/tool-calling/anthropic.md)
- Hand-written schema: tool `exa_search` with required `query` and `objective`. The `objective` description, which Exa says to use "verbatim": "Goal for this search turn; say which documents should rank first, which should be excluded, and what specific facts or figures to pull from them." It is called as `exa.search(query=..., objective=..., type="auto", contents={"highlights": True})`. — [Anthropic Tool Calling](https://exa.ai/docs/integrations/tool-calling/anthropic.md), [Search best practices](https://exa.ai/docs/search/best-practices.md)
- Query style (from the MCP tool description): "describe the ideal page, not keywords. 'blog post comparing React and Vue performance' not 'React vs Vue'… If highlights are insufficient, follow up with web_fetch_exa on the best URLs." — [webSearch.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/webSearch.ts)
- Agent prompting via MCP: `agent_run` is described as "Use it instead of running many searches yourself when a task needs multiple searches, cross-source verification, or a structured table of results… Not for a single question or lookup." — [agentRun.ts](https://github.com/exa-labs/exa-mcp-server/blob/main/src/tools/agentRun.ts)
- Other official integrations exist for the Vercel AI SDK (`@exalabs/ai-sdk`), OpenAI tool calling, LangChain, LlamaIndex, CrewAI, Pydantic AI, AG2 and others, plus Agent Skills (`npx skills add exa-labs/agent-skills`; skill file `https://exa.ai/docs/skill.md`). — [llms.txt](https://exa.ai/docs/llms.txt)

### Inferences
- Inferred: the Exa sample uses `claude-sonnet-4-6`. Our project policy needs Opus 5.5 or Fable 5.2 models, and the helpers are model-agnostic.

### Gaps
- I did not read the LangChain, LlamaIndex, CrewAI or Vercel pages in full. They are listed in llms.txt only. (The Anthropic page is the one that matters for our stack.)
